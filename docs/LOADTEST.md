# Навантажувальне тестування

Для перевірки роботи REST API під навантаженням
використовувалася програма k6.

## Сценарій тестування

Сценарій знаходиться у файлі loadtest/loadtest.js.

Тест імітує роботу користувачів із музичним REST API.

Один віртуальний користувач виконує одну операцію
запису та дев'ять операцій читання.

Операція запису:
- Створення нової пісні.

Операції читання:
- Отримання списку пісень.
- Отримання окремої пісні.
- Отримання профілю користувача.

## Параметри

- Кількість віртуальних користувачів (N): 20
- Наростання навантаження: 3 хвилини
- Стале навантаження: 5 хвилин
- Зменшення навантаження: 2 хвилини
- Загальна тривалість тестування: 10 хвилин

Кількість користувачів N = 20 була обрана для того,
щоб під час тестування спрацювало автоматичне
масштабування Azure Container Apps.

## Запуск тестування

Спочатку потрібно перейти в корінь проєкту
та налаштувати змінні середовища для підключення
до API й авторизації тестового користувача.

Публічна адреса API:

http://20.100.173.25

Команда запуску:

    k6 run .\loadtest\loadtest.js

Після запуску k6 автоматично виконує всі три фази.

- Загальна кількість HTTP-запитів: 25 622
- Кількість виконаних ітерацій: 2562
- Середня кількість запитів за секунду: 42,60
- Успішні перевірки: 100%
- Частка HTTP-помилок: 0%
- Середній час відповіді: 254,89 мс
- Мінімальний час відповіді: 43,73 мс
- Максимальний час відповіді: 3,89 с

Показники латентності:

- p50: 95,71 мс
- p95: 982,16 мс
- p99: 1790 мс

p50 означає, що половина запитів виконалася
за 95,71 мс або швидше.

p95 означає, що 95% запитів виконалися
за 982,16 мс або швидше.

p99 означає, що 99% запитів виконалися
за 1790 мс або швидше.

## Результати масштабування

До початку тестування працювала одна репліка.

Під час збільшення навантаження кількість реплік
автоматично зросла до трьох.

Після завершення тестування кількість реплік
спочатку зменшилася до двох, а потім до однієї.
