# Music Library API

## Опис застосунку

**Music Library API** — REST API для керування музичною бібліотекою, розроблений на Python із використанням FastAPI та PostgreSQL.

Застосунок дозволяє переглядати, додавати та видаляти пісні. Для захисту операцій запису реалізовано JWT-автентифікацію користувачів.

Для розгортання використано Docker, Terraform і Microsoft Azure. Автоматичне оновлення API налаштовано через GitHub Actions.

У лабораторній роботі №2 додано автоматичне масштабування, моніторинг, кешування Redis, асинхронну обробку через Azure Service Bus, ідемпотентність запитів і масштабування за розкладом.

Адреса працює, коли Azure Application Gateway увімкнений. Під час економії коштів шлюз може бути зупинений.

## Основні можливості

- Перегляд списку пісень та інформації про окрему пісню.
- Створення і видалення пісень із JWT-автентифікацією.
- Асинхронне створення пісень через чергу повідомлень.
- Перевірка стану асинхронного завдання.
- Кешування списку пісень у Redis.
- Захист від повторного створення пісень за допомогою `Idempotency-Key`.
- Автоматичне масштабування API та контейнера-обробника.
- Моніторинг метрик і сповіщення про проблеми.

## Основні API-запити

| Метод | Адреса | Призначення |
| --- | --- | --- |
| `GET` | `/health` | Перевірка API та PostgreSQL |
| `GET` | `/songs` | Список пісень |
| `GET` | `/songs/{song_id}` | Інформація про пісню |
| `POST` | `/songs` | Створення пісні |
| `DELETE` | `/songs/{song_id}` | Видалення пісні |
| `POST` | `/songs/async` | Асинхронне створення пісні, відповідь `202 Accepted` |
| `GET` | `/jobs/{job_id}` | Перевірка стану завдання |
| `GET` | `/cache/stats` | Статистика Redis-кешу |
| `POST` | `/auth/register` | Реєстрація користувача |
| `POST` | `/auth/token` | Отримання JWT-токена |
| `GET` | `/auth/me` | Інформація про поточного користувача |

Операції запису та перевірка завдань вимагають авторизації. Для `POST /songs/async` можна передати заголовок `Idempotency-Key`, щоб повторний запит повернув попередню відповідь без нового завдання.

## Хмарна інфраструктура

Основні ресурси розгорнуті в Microsoft Azure, регіон **Norway East**:

- **Azure Container Apps** — `ca-music-api`, REST API.
- **Azure Container Apps** — `ca-music-worker`, обробник повідомлень.
- **Azure Database for PostgreSQL Flexible Server** — база даних `musicdb`.
- **Azure Managed Redis** — кешування та ідемпотентність.
- **Azure Service Bus** — черга `music-tasks`.
- **Azure Application Gateway** — публічний доступ до API та балансування навантаження.
- **Azure Container Registry** — зберігання Docker-образів.
- **Azure Monitor і Log Analytics** — метрики, Dashboard та сповіщення.

Усі основні налаштування інфраструктури описані за допомогою Terraform.

## Масштабування та кешування

API масштабується за HTTP-навантаженням до **3 реплік**. Додатково налаштовано розклад за київським часом:

- **08:00–22:00** — щонайменше 2 репліки.
- **22:00–08:00** — можливе масштабування до 0 реплік за відсутності запитів.

Worker окремо масштабується від кількості повідомлень в Azure Service Bus у межах **0–3 репліки**.

Redis зберігає список пісень протягом **60 секунд**. Після створення або видалення пісні кеш очищається. Результати запитів із `Idempotency-Key` зберігаються в Redis **24 години**.

## Навантажувальне тестування

Для тестування використовується **k6**:

- `loadtest/loadtest.js` — перевірка REST API під навантаженням.
- `loadtest/queue.js` — перевірка асинхронного створення пісень.

Тестування підтвердило роботу API під навантаженням, автоматичне масштабування та обробку повідомлень через чергу.
